# Autonomous Road Safety – Computer Vision Implementation

This implementation follows the requested structure of the reference GitHub project: a Python application, requirements file, test suite, asset generator, model/calibration folder, templates, static resources and outputs.

## Pipeline
Video/Camera → Calibration & Undistortion → Preprocessing → YOLO Detection → Sign/Marking Recognition → ByteTrack Association → Occlusion Management → Hazard Logic → Annotated Video + Metrics

## Main components
- **OpenCV:** frame processing, calibration/undistortion, CLAHE preprocessing, Canny + Hough lane detection.
- **YOLO (Ultralytics):** vehicles, pedestrians, traffic lights and stop-sign detection using a lightweight YOLOv8 model.
- **ByteTrack:** persistent IDs for video tracking through Ultralytics `track(..., tracker="bytetrack.yaml")`.
- **Occlusion management:** tracking persistence plus detection of crowded/overlapping objects; ByteTrack handles association through consecutive frames.
- **Safety logic:** pedestrian-in-road-corridor warning and SAFE/HIGH-RISK state.
- **Metrics:** object count, frame count, average latency and FPS are written to `outputs/metrics.json`.

## Run on Windows
```text
cd Implementation
pip install -r requirements.txt
python generate_assets.py
python app.py
```
Open `http://127.0.0.1:5000`.

For video input, the application uses ByteTrack. For image input, it produces an annotated image and performs image-level overlap/safety analysis.

## Model
If `models/yolov8n.pt` is absent, Ultralytics can download the model on first execution when internet access is available. For offline execution, place the model file in `models/`.

## Important academic note
The calibration values generated by `generate_assets.py` are demo values. For a final experiment, replace them with parameters obtained from the actual camera/calibration sequence. FPS, latency and detection metrics should be reported from the machine and dataset used for the experiment.
